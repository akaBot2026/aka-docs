# Configuration Changes by Version (5.x)

This page lists changes introduced by each V5 release and settings to review for the exact target version. The baseline is **Center 4.0.0.14**. For preparation, complete key/value comparisons, common migration actions, AI setup, and YAML examples, see the [configuration reference](/docs/center/latest/installation/configuration-migration-4x-to-5x.md). Apply common changes first; later branches do not necessarily include every setting from another branch.

**Required** describes whether an upgrade action is needed, not whether a key was renamed:

- **Conditional:** update only if Update Condition matches and the target V5 profile/configuration does not already meet that requirement. This includes incompatible overrides, actual database settings, HA/AI, and required monitoring behavior. A renamed key with a suitable bundled value does not require a new declaration.
- **Yes (review):** review workflow retention before first startup because bundled dev/prod profiles enable cleanup. Retain the value if appropriate; change it only when cleanup is not permitted. This is a required review, not an unconditional value change.
- **No:** no mandatory change solely for the upgrade is identified. Keep suitable values. Optional tuning, internal help URLs, and recommended legacy cleanup remain documented; existing valid environment-specific settings must still be preserved.

No row requires a value change in every deployment simply because its key or sample value changed. Read the active profile and external overrides together: base YAML values can be overridden by dev/prod files, environment variables, or service options.

For legacy declarations, follow the listed migration action to match the target YAML; this classification does not claim that every old key causes startup failure. Optional values become relevant when operations require different behavior. For grouped rows, read each referenced configuration's condition rather than applying every setting unconditionally.
