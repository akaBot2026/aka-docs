# Akabot Centerセキュリティ概要

**ドキュメントの目的：** 顧客向けセキュリティ概要  
**製品：** Akabot Center  

## 1. 概要

Akabot Centerは、Akabotの自動化を一元的にオーケストレーションおよび管理するプラットフォームです。そのセキュリティモデルは多層構造になっており、プラットフォームへのアクセス、自動化の認証情報、運用データ、管理機能を保護します。

本書は、Akabot Centerを評価または運用する顧客のセキュリティ部門、リスク管理部門、IT部門を対象としています。既定の設定や利用可能な機能はバージョンによって異なる場合があるため、お使いのバージョンの[リリースノート](../release-notes.md)をご確認ください。

主な管理策は次のとおりです。

- 署名付きトークンによる、認証済みで有効期限のあるアクセス
- ロールベースおよびリソース単位の認可
- 組織単位によるデータの分離
- パスワードの一方向ハッシュ化、および特定のシークレットの暗号化
- TLSで保護された通信および外部シークレットマネージャーへの対応
- 設定可能な多要素認証、パスワード ポリシー、アカウントロックアウト
- セキュリティを重視したブラウザヘッダー
- 認証およびビジネスデータの監査証跡

一部の管理策は、Akabot Centerを導入する環境によって補完されます。これには、TLSの終端、データベースの暗号化、ストレージの暗号化、鍵の保管、バックアップの保護、ネットワークの分割が含まれます。これらの責任分担については、12項に示しています。

Akabotが製品をどのように開発、テスト、リリース、サポートしているかについては[セキュアな製品開発プロセス](./secure-product-development.md)に記載しています。Akabotシステム全体のアーキテクチャ、データフロー、責任範囲については[技術セキュリティおよびデータフローの説明](../../../legal/latest/technical-security-and-data-flow-description.md)に記載しています。

## 2. セキュリティアーキテクチャの概要

| セキュリティ上の目的 | 適用する手法 | 顧客にとっての利点 |
|---|---|---|
| アカウントの保護 | パスワードのハッシュ化、設定可能なパスワード ポリシー、任意の多要素認証、アカウントロックアウト | パスワードの漏えいやアカウント乗っ取りのリスクを低減します |
| リクエストの認証 | 有効期限付きの署名付きアクセストークン、およびマネージドAPIトークン | 保護されたAPIが認証なしで利用されることの防止に役立ちます |
| ユーザーができる操作の制限 | リソースごとに権限レベルを設定したロール | 最小権限でのアクセスを支援します |
| ビジネスデータの分離 | 組織単位 | ユーザーが、使用を許可されたデータの範囲内にとどまるようにします |
| 保存された機密値の保護 | 特定の認証情報の暗号化、および外部シークレットマネージャーとの連携 | 運用上の認証情報が露出するリスクを低減します |
| ネットワーク通信の保護 | HTTPS（TLS）への対応 | TLSを正しく導入した場合に、転送中のデータを保護します |
| 説明責任の支援 | 認証イベントおよびビジネスデータの変更履歴 | 顧客がアクセスや運用上の変更を調査する際に役立ちます |
| ブラウザインターフェースの強化 | ブラウザのセキュリティヘッダー | ブラウザを経由する一般的な攻撃経路を減らします |

## 3. 認証とセッションのセキュリティ

### 3.1 対応する認証方式

Akabot Centerは、顧客のID管理の構成に適合できるよう、複数のサインイン方式に対応しています。

- Akabot Centerのローカルアカウント
- LDAPまたはActive Directoryとの連携
- システム間アクセス用のマネージドAPIトークン（[センターのマネージドトークンの使用方法](../user-guide/managed-token.md)を参照）
- Akabot Centerと自動化エージェント間の通信に使用する、専用のロボットID

どのID連携を使用するかは導入環境によって異なります。顧客は、自社のIDおよびアクセス管理ポリシーに従って設定してください。

### 3.2 パスワードの保護

ローカルユーザーのパスワードは平文で保存されません。Akabot Centerは、各パスワードのソルト付き一方向ハッシュを保存し、送信されたパスワードをそのハッシュと照合するため、データベースからパスワードを復号することはできません。

管理者は、[Password Policy（パスワード ポリシー）](../user-guide/how-to-use-by-function/operation-functions/administration/password-policy.md) 画面でパスワード ポリシーを設定できます。ポリシーには次の項目を含めることができます。

- パスワードの最小文字数
- 大文字、小文字、数字、特殊文字の必須化
- 推測されやすいキーボード配列のチェック
- 使用禁止語リストとの照合
- パスワードの有効期限
- 最近使用したパスワードの再利用の防止
- 初回ログイン後または管理者によるリセット後のパスワード変更の必須化
- ログインの失敗が繰り返された場合のアカウントロックアウト

標準の構成では、パスワードは最小文字数を満たし、大文字、小文字、数字、特殊文字を含む必要があります。アカウントロックアウトは有効になっています。その他の管理策は任意であり、顧客は自社のパスワード ポリシーに従って有効にしてください。

### 3.3 多要素認証

Akabot Centerは、Google AuthenticatorやMicrosoft Authenticatorなどの標準的な認証アプリを使用した、時間ベースのワンタイムパスワード（TOTP）による多要素認証（MFA）に対応しています。MFAを有効にする前に、ユーザーは認証アプリのコードで設定を確認します。また、認証アプリを利用できない場合に使用するバックアップコードも受け取ります。認証アプリとバックアップコードの両方にアクセスできなくなった場合は、管理者がユーザーのMFAをリセットできます。

管理者は、MFAの適用方法を選択できます。

- **Allow users to enable MFA（ユーザーに MFA の有効化を許可する）。** MFAは任意です。ユーザーまたは管理者が、個々のアカウントで有効にします。
- **Enforce MFA for all users（すべてのユーザーに MFA を強制する）。** すべてのユーザーは、システムを使用する前にMFAを設定する必要があります。

標準の構成では、MFAは利用できますが、必須ではありません。Akabotは、特に管理者に対してMFAを強制することを推奨します。Akabot Center Cloudでは、すべてのアカウントで二段階認証が必須です。手順については[Center Cloud の二段階認証](../user-guide/how-to-use-by-function/center-overview/two-step-verification.md)をご覧ください。

### 3.4 トークンのセキュリティ

サインインに成功すると、Akabot Centerは署名付きのJSON Web Token（JWT）を発行し、クライアントは各リクエストでこれを送信します。Akabot Centerは次の処理を行います。

- 各トークンに署名し、保護されたリクエストごとに署名と有効期限を確認する
- ユーザーの権限をトークンに含める
- アカウントの状態を確認し、関連するアカウントの変更によって、それまでのアクセスを終了できるようにする

トークンの有効期間は設定可能です。ユーザーがサインイン状態の維持を選択した場合は、より長い有効期間が適用されます。顧客は、リスクポリシーで必要な場合には、トークンの有効期間を短く設定してください。

## 4. ロール、権限、最小権限

Akabot Centerは、ロールによってアクセスを制御します。ロールはリソースに対する権限のセットであり、ユーザーは割り当てられたロールを通じてのみアクセス権を得ます。詳細については、[ロール管理](../user-guide/how-to-use-by-function/operation-functions/administration/role-management.md)および[ユーザー管理](../user-guide/how-to-use-by-function/operation-functions/administration/user-management.md)をご覧ください。

### 4.1 標準ロール

| ロール | 想定される用途 |
|---|---|
| 管理者（ROLE_ADMIN） | プラットフォームの管理。既定では、このロールはすべてのリソースに対するすべての権限を持ち、これは変更できません。 |
| ユーザー（ROLE_USER） | 業務機能および自動化機能への、人による利用。既定の権限は編集できます。 |
| ロボット（ROLE_ROBOT） | 自動化エージェント用の制限付きID。既定の権限は編集できます。 |

管理者は、独自のロールを作成することもできます。

### 4.2 リソースと操作の権限

権限はリソースごとに設定します。リソースは、Admin（管理）、Environment（環境）、Robot（ロボット）、Package（パッケージ）、Workflow（ワークフロー）、Job（ジョブ）、Schedule（スケジュール）、Organization Unit（組織単位）、Asset（資産）、Queue（キュー）、Log（ログ）です。ロールには、リソースごとに次のいずれかのレベルが設定されます。

| レベル | ユーザーができる操作 |
|---|---|
| None（なし） | リソースはインターフェースに表示されません。 |
| View（表示） | リソースを表示できますが、変更はできません。 |
| Edit（編集） | リソースを表示および編集できます。 |
| Create（作成） | リソースを表示し、新しいリソースを作成できます。 |
| Delete（削除） | リソースを削除できます。 |

保護された操作は、サーバー側で確認されます。機能をインターフェース上で非表示にすることは、唯一の管理策ではありません。APIも、保護された操作を実行する前に、サインインしているユーザーの権限を確認するためです。

管理者は、設計上、広範なアクセス権を持ちます。顧客は、管理者の人数を限定し、管理者アカウントを共有せず個人ごとに割り当て、管理者に対してMFAを有効にし、管理者の操作内容を確認してください。

## 5. 組織単位によるデータの分離

組織単位（OU）は、指定されたユーザーに対して、Akabot Centerを個別のテナントに分割します。Akabot Centerでユーザーに表示される内容は、そのユーザーが所属する組織単位と、割り当てられたロールによって決まります。組織単位に割り当てられていないユーザーは、リソースにアクセスできません。エージェントを2つの組織単位にプロビジョニングすることはできず、リソースを組織単位間で移動することもできません。詳細については[組織単位](../user-guide/how-to-use-by-function/operation-functions/administration/organization-unit.md)をご覧ください。

Akabot Centerは、ユーザー、APIトークン、またはロボットが、該当する組織単位で操作することを許可されているかを、サーバー側で確認します。

この管理策により、1つのAkabot Centerの導入環境内で論理的な分離が実現されます。テナント間で物理的またはデータベースレベルの分離が必要な顧客にとって、別のインフラストラクチャの代わりとなるものではありません。

## 6. 保存データの暗号化と保護

Akabot Centerは、データの種類に応じて異なる方法で保護します。

### 6.1 アプリケーションが保護する値

| データの種類 | 保護方法 |
|---|---|
| ローカルユーザーのパスワード | 一方向ハッシュ化。保存されたハッシュからパスワードを復号することはできません。 |
| [資産](../user-guide/how-to-use-by-function/operation-functions/assets.md)として保存された認証情報、および特定のロボットや連携の認証情報 | AES-256アルゴリズムで暗号化されます。 |
| MFAのシークレットおよびバックアップコード | 暗号化された形式で保存されます。 |
| 構成ファイル内の機密値 | 暗号化された値に対応しています。 |
| 外部シークレットマネージャーに保管される認証情報 | HashiCorp VaultおよびAWS Secrets Managerに対応しています。9項をご覧ください。 |

アプリケーションによる暗号化は、特定のシークレットに適用されます。ビジネスデータのすべての列がアプリケーションによって暗号化されるわけではありません。

### 6.2 データベース、ファイル、インデックス、ログ、バックアップ

データベースボリューム全体、ファイルストレージ、検索インデックス、ログ、スナップショット、バックアップの暗号化は、Akabot Centerが稼働する環境の責任です。顧客は、データベース、クラウドプラットフォーム、ストレージシステム、またはオペレーティングシステムの保存時の暗号化機能を使用し、承認された鍵管理サービスで鍵を管理してください。

高い保証が求められる導入環境では、Akabotは、本番環境の暗号鍵およびシークレットマネージャーの認証情報について、次の対応を推奨します。

- アプリケーションパッケージおよびソース管理の外部から提供する
- 必要とするサービスIDのみが利用できるようにする
- 承認された手順でローテーションする

## 7. 転送中データの保護

### 7.1 ブラウザおよびAPIの通信

Akabot Centerは、ブラウザおよびAPIの通信にHTTPS（TLS）を使用できます。アプリケーションサーバー、またはリバースプロキシやロードバランサーでHTTPSを有効にすると、TLSにより、認証情報、アクセストークン、リクエスト、レスポンスが盗聴や改ざんから保護されます。ブラウザがHTTPSでサービスに接続すると、HTTP Strict Transport Security（HSTS）ポリシーにより、以降のアクセスでもHTTPSを使用するよう指示されます。

TLSは、顧客の導入環境で設定します。本番環境では、信頼できる証明書でTLSを終端し、現行のプロトコルバージョンと承認された暗号スイートのみを許可してください。[高可用性の導入ガイド](../installation/ha-model-windows-server.md)に、リバースプロキシの設定例を記載しています。

### 7.2 データベースおよびサービスへの接続

Akabot Centerからデータベース、LDAPディレクトリ、メッセージブローカー、キャッシュ、その他の連携サービスへの接続は、顧客が選択する製品とその接続設定によって異なります。本番環境では、顧客はこれらの接続のそれぞれでTLSを使用するよう設定してください。

### 7.3 CenterとAgent間の通信

Akabot Centerは、3.1項に記載のとおり、専用のロボットIDを使用して自動化エージェントと通信します。顧客は、7.1項に記載のとおり、Akabot Centerとエージェント間のネットワーク接続をTLSで保護してください。

## 8. APIおよびWebアプリケーションの保護

Akabot Centerは、Webレイヤーで次の管理策を適用しています。

- ビジネスAPIには認証が必要です。ただし、サインイン、アクティベーション、ヘルスチェック、静的コンテンツ、その他の公開を目的としたエンドポイントを除きます。
- 管理者向けAPIおよびAPIドキュメントには、管理者権限が必要です。
- 実行環境、構成、ログ、スレッドダンプ、キャッシュ管理などの機密性の高い管理エンドポイントは、公開インターフェースからは利用できません。
- クロスオリジンリソース共有（CORS）は既定でオフになっており、オンにした場合も制限できます。
- 特定のエンドポイントには、クライアントIPアドレスごとにレート制限を設定できます。標準の構成ではオフです。顧客は、信頼できないネットワークから到達可能なサインインエンドポイントでこれをオンにし、APIゲートウェイまたはWebアプリケーションファイアウォールでもレート制限を追加してください。

### 8.1 ブラウザのセキュリティヘッダー

Akabot Centerは、次のブラウザセキュリティヘッダーを使用します。

- **Content-Security-Policy**は、スクリプト、フレーム、画像、フォント、ネットワーク接続の取得元を制限します。
- **X-Frame-Options**は、インターフェースがフレーム内に表示されることを防ぎ、クリックジャッキングのリスクを低減します。
- **X-Content-Type-Options**は、ブラウザによるコンテンツタイプの推測を防ぎます。
- **Strict-Transport-Security**は、ブラウザにHTTPSを使用するよう指示します。
- **Referrer-Policy**は、共有されるリファラー情報の量を制限します。
- **Permissions-Policy**は、カメラ、マイク、位置情報など、Akabot Centerで不要なブラウザ機能を無効にします。

## 9. シークレット管理

Akabot Centerは、アプリケーション設定や自動化の認証情報などの機密値をHashiCorp VaultおよびAWS Secrets Managerから取得できるため、必要なときに取得でき、通常の構成ファイルに保存しておく必要がありません。設定方法については[Vault を使用するように akaBot Center を構成する](../installation/configure-vault.md)をご覧ください。

外部シークレットマネージャーを使用する顧客は、次の対応を行ってください。

- Akabot Center専用のワークロードIDを付与する
- 必要なシークレットのパスのみにアクセスを許可する
- TLSを使用し、シークレットマネージャーの証明書を検証する
- 定められたスケジュールで認証情報と暗号鍵をローテーションする
- シークレットの読み取りおよび管理上の変更を監査する
- サービスが使用するローカルキャッシュまたはメモリ内キャッシュへのアクセスを制限する

## 10. 監査可能性とモニタリング

Akabot Centerは、2種類の監査記録を保持します。

- **認証およびセキュリティイベント**（サインインの成功と失敗、セッションなど）
- **エンティティの変更履歴**（ユーザーやタスクなどのビジネスデータに対する作成、更新、削除の操作を記録）

監査記録には、誰がいつ操作を行い、何が変更されたかなどの詳細が含まれます。監査機能へのアクセスは権限によって制御されます。管理者は [Clean Data（データクリーン）](../user-guide/how-to-use-by-function/operation-functions/administration/clean-data.md) 画面で、監査記録やその他の運用データの保持期間を設定できるため、保持期間を顧客のポリシーに合わせることができます。

顧客は、Akabot Center、オペレーティングシステム、リバースプロキシ、データベース、シークレットマネージャーのログを、保護された一元的なモニタリングまたはSIEMプラットフォームに転送してください。監査記録および保持期間の設定へのアクセスは、権限のある担当者に限定してください。

## 11. ペネトレーションテスト

Akabot Centerは、「[セキュリティテスト](./secure-product-development.md#51-セキュリティテスト)」に記載のセキュリティテスト（ペネトレーションテストを含む）の対象です。テストで見つかったセキュリティ上の問題は製品リリースで修正され、その修正内容は[リリースノート](../release-notes.md)に記載されます。

ペネトレーションテストは、ある時点での評価です。これは、顧客による安全な構成、パッチ適用、モニタリング、アクセスレビュー、定期的な再評価を補完するものです。

## 12. セキュリティ上の責任分担

Akabot Centerはアプリケーションの管理策を提供します。顧客、またはAkabot Centerをホストする運用事業者は、稼働する環境を保護します。

| 領域 | Akabot Centerが提供するもの | 顧客またはホスティング運用事業者が担うもの |
|---|---|---|
| ID | 認証、トークンの検証、ロールと権限、任意のMFA | IDプロバイダーのセキュリティ、アカウントのライフサイクル、MFAの強制、アクセスの定期的なレビュー |
| ネットワーク | HTTPSへの対応、保護されたAPI、ブラウザのセキュリティヘッダー | 信頼できるTLS証明書、プロトコルおよび暗号スイートのポリシー、ファイアウォール、ネットワークの分割、WebアプリケーションファイアウォールまたはAPIゲートウェイ |
| 保存データ | パスワードのハッシュ化、特定のシークレットの暗号化 | データベース、ストレージ、バックアップの暗号化、鍵管理、バックアップへのアクセス、リカバリのテスト |
| シークレット | 暗号化された構成値、VaultおよびAWS Secrets Managerへの対応 | シークレットマネージャーの可用性、アクセスポリシー、鍵の保管、ローテーション |
| プラットフォーム | アプリケーションの認可機能および監査機能 | オペレーティングシステム、データベース、Javaランタイム、コンテナ、プロキシのパッチ適用とハードニング |
| モニタリング | アプリケーションイベントおよび監査イベント | ログの一元収集、アラート、インシデント対応、時刻同期、ログの保持 |
| 可用性 | 設定可能なデータ保持 | 耐障害性のあるアーキテクチャ、キャパシティ、データベースの高可用性、災害復旧、リストアのテスト |

## 13. 本番環境で推奨されるセキュリティベースライン

Akabot Centerを本番環境のユーザーに提供する前に、Akabotは顧客が次の対応を行うことを推奨します。

1. 信頼できる証明書を使用し、HTTPSでのみサービスを公開する。
2. データベース、ストレージボリューム、ログ、スナップショット、バックアップを暗号化する。
3. 本番環境の鍵と認証情報を、管理されたシークレットストアに保管し、ローテーションする。
4. 特に管理者に対して、MFAを強制する。
5. トークンの有効期間を見直し、不要な場合は長期間有効なセッションを避ける。
6. アカウントロックアウトを有効のままにし、想定されるトラフィックに適したレート制限を有効にする。
7. LDAPなどのインフラストラクチャサービスにTLSで接続する。
8. 各ユーザーに必要な最小限のロール、リソース、組織単位の権限のみを付与する。
9. 公開する必要のないヘルスチェックおよびモニタリングのエンドポイントへのネットワークアクセスを制限する。
10. 監査ログおよびセキュリティログを一元的に収集し、不審なアクティビティに対するアラートを設定する。
11. Akabot Centerおよびその依存関係のサポート対象アップデートを速やかに適用する。
12. 特に大きな変更の後は、定期的に脆弱性スキャンとペネトレーションテストを実施する。
