# ワークフロー

**ワークフロー**は、**パッケージ**と**エージェント グループ**の間の関連付けを表します。パッケージが**エージェント グループ**にリンクされるたびに、その**エージェント グループ**に属するすべてのエージェント マシンに自動的に配布されます。

「ワークフロー」ページでは、アップロードされたパッケージをエージェント グループに展開し、以前に作成した関連付けを管理し、すべてのワークフローを最新の状態に保つことができます。これにより、エージェント マシンにパッケージを配布し、「タスク」ページから作業をより迅速に実行できるようになります。「ワークフロー」ページにアクセスするには、左側のメニューの「ワークフロー」タブをクリックします。クリックすると、以下のように既存のすべてのワークフローを一覧表示するワークフロー ページが表示されます。

![image-20221028093815-5.png](/static/img/image-20221028093815-5.png)

| いいえ | 列/ラベル | 説明 |
| --- | --- | --- |
| 1 | アクション | 当該ワークフローのログを管理するために利用可能なアクション。含まれるもの：<br/><br/>* VIEW：「タスクの詳細」ページにリダイレクトされます。<br/>* EDIT：各ワークフローの詳細を編集できます。<br/>* DELETE：選択したワークフローをセンターから削除できます。<br/>* START JOB：このワークフローに関連する新しいタスクをすばやく作成します。<br/>* ADD SCHEDULE：このワークフローに関連するスケジュールをすばやく追加します。<br/><br/>各ワークフローに対応するチェックボックスを選択すると、フィルター オプションの横に削除オプションが表示され、ワークフローを削除できるようになります。「アクション」の横にあるチェックボックスを選択すると、表示されているすべてのワークフローが選択され、選択したワークフローを一括削除できます。 |
| 2 | ワークフロー名 | ワークフローの名前。整理のために、**パッケージ名\_エージェント グループ名** の形式でワークフロー名を作成することをお勧めします。 |
| 3 | パッケージ名 | akaBot Center に公開されたパッケージの名前 |
| 4 | パッケージバージョン | akaBot Center に公開されたパッケージのバージョン。パッケージのバージョンは、akaBot Studio で公開オプションを選択したときに決定されます。 |
| 5 | エージェントグループ | ワークフローが展開されるエージェント グループ |
| 6 | 説明 | パッケージの公開されている説明の現在のバージョン |
| 7 | 作成者 | このワークフローを作成したユーザー。 |

## **ワークフロー保持ポリシー**

**ワークフロー保持ポリシー**は、akaBot Center の機能であり、ワークフローの実行履歴（ログおよびタスクの記録を含む）が自動的に削除されるまでの保持期間を制御します。

保持ポリシーを設定しない場合、実行履歴は無期限に蓄積されます。時間の経過とともに、これによりワークフロー ページの動作が遅くなり、ストレージの使用量が増加する可能性があります。ポリシーを設定することで、管理者はスケジュールに従って古くなった実行データのクリーンアップを自動化できます。

デフォルトでは、この機能が導入される前に作成された古いワークフローはログを永続的に保持します。ただし、新規に作成されるワークフローや既存のワークフローを更新する場合は、カスタム保持ポリシーの設定が必須です。

### **保持ポリシーのパラメータ**

保持ポリシーの設定パネルには、以下のパラメータが含まれています。

| いいえ | 列/ラベル | 説明 | 種類 | デフォルト値 | 必須ですか？ | 制約/要件 |
| :---- | :------------------------------ | :--------------------------------------------------------------------------------------- | :------------- | :-------------------------- | :------------------- | :------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 1 | **保持ポリシーの選択** | すべての記録を無期限に保持するか、カスタムのクリーンアップ ルールを設定するかを選択します。 | トグル オプション | 永続的に保持 | はい（更新時） | • ポリシーのない古いワークフローを更新する場合にのみ利用可能です。<br/>• ワークフロー作成時は、このオプションは非表示となり、カスタム保持の設定が必須です。 |
| 2 | **保持期間（日数）** | 実行データが削除される前にデータベースに保持される期間（日数）。 | 数値入力 | 30日 | はい | • 最小値：`7`<br/>• 最大値：`180`<br/>• 正の整数である必要があります。無効な値を入力するとエラーメッセージが表示され、**保存**ボタンが無効になります。 |
| 3 | **適用するタスク状態** | クリーンアップをトリガーする実行結果を選択します。 | チェックボックス | なし（要選択） | はい | 選択可能なオプション：<br/>• `成功`<br/>• `失敗`<br/>• `停止済み`<br/>• `保留中`<br/>• `停止中`<br/>• `終了中` |
| 4 | **クリーンアップ範囲** | 保持期間を超えた際の削除範囲を定義します。 | ラジオボタン | ログのみ削除 | はい | オプション：<br/>• **ログのみ削除**：実行ログを削除しますが、タスクは保持します。<br/>• **完全クリーンアップ**：実行ログとタスクの両方を完全に削除します。 |

### **ワークフロー作成時の保持ポリシーの設定**

ワークフロー ページの上部にある**「新規作成」**ボタンをクリックして新しいワークフロー関連付け（NuGet パッケージをエージェント グループにリンク）を作成する場合、保持ポリシーの設定は必須です。

![create-workflow-center](/static/img/create-workflow-center.png)

1. 必須の一般フィールドを入力します：**パッケージ名**、**パッケージバージョン**、および**エージェントグループ**。
2. ダイアログの下部までスクロールして、**保持ポリシー**セクションを表示します。
3. **保持期間**を指定します（7〜180日の整数である必要があります）。
4. **適用するタスク状態**で 1 つ以上の実行状態にチェックを入れます。
5. **クリーンアップ範囲**を選択します（*ログのみ削除*または*完全クリーンアップ*）。

   ![workflow-center](/static/img/workflow-center.png)

6. **保存**をクリックして、有効なポリシーと共にワークフローを展開します。

### **ワークフロー更新時の保持ポリシーの設定**

#### **カスタム保持ポリシーが設定済みのワークフロー**

カスタム保持ポリシーがすでに有効になっているワークフローの場合：

1. 一覧ページのワークフロー横にある**3 点**ボタンをクリックし、**編集**を選択します。

   ![edit-workflow-center](/static/img/edit-workflow-center.png)

2. **ワークフローの編集**ダイアログの**保持ポリシー**セクションまでスクロールします。各フィールドには現在の有効な値が表示されます。
3. **保持期間**、**適用するタスク状態**、および**クリーンアップ範囲**を必要に応じて変更します。
4. **保存**をクリックして変更を適用します。

#### **永続保持のワークフロー（有効なポリシーなし）**

保持設定を実装する前に作成されたワークフローの場合：

1. ワークフロー横にある**3 点**ボタンをクリックし、**編集**を選択します。
2. **保持ポリシー**セクションまでスクロールします。**永続的に保持**（デフォルトで有効）と**カスタム保持の設定**の 2 つのオプションが表示されます。

   ![keep-permanently](/static/img/keep-permanently.png)

3. カスタム ポリシーを設定するには、**カスタム保持の設定**を選択します。
4. デフォルトのプレースホルダー（例：30日、ログのみ削除）とともに設定フィールドが表示されます。
5. 希望の保持期間、タスク状態、およびクリーンアップ範囲を設定します。

   ![edit-workflow](/static/img/edit-workflow.png)

6. **保存**をクリックして新しいポリシーを保存します。

### **ワークフロー詳細ページでの保持ポリシーの確認**

ワークフローに設定された保持ポリシーを確認するには：

1. **ワークフロー一覧**ページで、対象のワークフロー横にある目のアイコン（**表示**）をクリックします。
2. ワークフロー詳細ページには、保持ポリシー情報が含まれる 2 つのタブがあります。

#### **「全般」タブ**

詳細ページの**全般**タブには、現在有効な保持ポリシーが表示されます：
* **保持ポリシー**：選択されたクリーンアップ アクションと期間が表示されます（例：`30日後に実行ログを削除`）。ワークフローがカスタム ポリシーで更新されていない古いレガシー ワークフローの場合は、`永続的に保持`と表示されます。
* **適用するタスク状態**：クリーンアップをトリガーする実行状態の一覧が表示されます（例：`成功`、`失敗`）。ポリシーが`永続的に保持`に設定されている場合、このフィールドは非表示になります。

![testlog-center](/static/img/testlog-center.png)

#### **「履歴」タブ**

**履歴**タブ（更新履歴）には、保持ポリシーへの変更を含む、ワークフローに行われたすべての変更の時系列ログが記録されます。ワークフローが編集されるたびに、新しいログエントリが作成されます。

履歴ログには、保持ポリシーに関連する以下の列が含まれています：

| いいえ | 列/ラベル | 説明 |
| :--- | :--- | :--- |
| 1 | **変更日時** | 変更が保存された日時。 |
| 2 | **パッケージバージョン** | 変更が行われた際に有効だったパッケージのバージョン。 |
| 3 | **保持アクション** | クリーンアップ期間とクリーンアップ範囲が表示されます（例：`15日 • 完全クリーンアップ` または `永続的に保持`）。 |
| 4 | **保持対象タスク状態** | クリーンアップ対象として設定されたタスク状態の一覧（例：`成功、失敗、停止済み`）。 |
| 5 | **説明** | ユーザーが入力した変更コメント。 |
| 6 | **作成者** | 変更を行ったアカウントのユーザー名。 |

![history-workflow-center](/static/img/history-workflow-center.png)

### **システム設定（application.yml）**

システム管理者向けに、バックグラウンド保持実行のグローバル動作および新規ワークフローのデフォルト値は、Center の `application.yml` 設定ファイルの `retention.workflow` パスの下で設定されます。

> **重要：** `application.yml` を変更した後は、変更を有効にするために **akaBot Center サービスを再起動する必要があります**。設定の変更は起動時にのみ読み込まれるため、実行中のインスタンスには適用されません。

デフォルトの YAML 設定構造は以下のとおりです：

```yaml
retention:
  workflow:
    enable: true
    cron: "0 0 2 * * ?"
    job-batch-size: 100
    log-batch-size: 200
    max-cleanup-iterations: 1000
    max-log-cleanup-iterations: 10000
    max-excluded-jobs: 900
    default-days: 30
    default-states: "SUCCESSFUL,FAULTED,STOPPED"
    default-log-only: true
```

以下に、各システム設定キーの詳細説明を示します：

| パラメータ | 種類 | デフォルト値 | 説明 |
| :--- | :--- | :--- | :--- |
| **enable** | ブール値 | `true` | バックグラウンドでのワークフロー保持クリーンアップ ジョブの自動実行を全体的に有効または無効にします。 |
| **cron** | 文字列 | `"0 0 2 * * ?"` | バックグラウンド クリーンアップ ジョブの実行スケジュールを定義する Cron 式（例：毎日午前 2 時）。 |
| **job-batch-size** | 整数 | `100` | 1 回のバッチで処理・削除されるタスク レコードの数を制限します。 |
| **log-batch-size** | 整数 | `200` | 1 回のバッチで処理・削除される実行ログの数を制限します。 |
| **max-cleanup-iterations** | 整数 | `1000` | ロック競合を防止するために、データベース クリーンアップで許可される最大ループ反復回数。 |
| **max-log-cleanup-iterations** | 整数 | `10000` | タイムアウトを防止するために、Elasticsearch/データベース ログ クリーンアップで許可される最大ループ反復回数。 |
| **max-excluded-jobs** | 整数 | `900` | 削除ルールから除外できるタスク レコードの最大数。 |
| **default-days** | 整数 | `30` | ワークフロー作成時に表示されるデフォルトの保持期間（日数）。 |
| **default-states** | 文字列 | `"SUCCESSFUL,FAULTED,STOPPED"` | ワークフロー作成時にデフォルトでチェックされる、カンマ区切りのタスク実行状態。 |
| **default-log-only** | ブール値 | `true` | ワークフロー作成時のデフォルトのクリーンアップ範囲（`true` = ログのみ削除、`false` = 完全クリーンアップ）。 |
