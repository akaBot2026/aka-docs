# 技術セキュリティおよびデータフローの説明

## 1. 適用範囲

本書は、利用規約、プライバシーおよびデータ処理ポリシー、ならびにAIサービスおよびデータ処理に関する補足条項とあわせて読むものとする。本書は次の事項について説明する:

- 導入アーキテクチャ;
- データの保存場所;
- 外部接続;
- AIデータフロー;
- セキュリティ管理策;
- 責任の境界。

実際のアーキテクチャは、バージョンおよび各顧客の導入設計により異なる場合がある。

## 2. 現行の参照アーキテクチャ

主なコンポーネントには次を含むことがある:

**Akabot Center**

エージェント、利用者、ワークフロー、スケジューリング、アセット、監視および運用情報を管理する。

**AI Hub**

AIプロバイダーとの接続、認証情報、モデルへのアクセス、割り当ておよび関連するAI機能を管理する。

**Data Service**

自動化に使用されるデータの管理または交換のための機能を提供する。

**Akabot Studio**

利用者のコンピュータにインストールされるワークフロー開発アプリケーションである。

**Akabot Agent**

顧客が指定するコンピュータまたはサーバー上でワークフローを実行するランタイムである。

これらのコンポーネントは、将来のバージョンで変更されることがある。

## 3. 導入境界

参照アーキテクチャ:

**顧客環境**

利用者  
↓

↓  
Center / AI Hub / Data Service  
↓  
Agent  
↓

↓

↓

## 4. データ保存場所マトリクス

| データ区分 | デフォルトの保存場所 | 外部への送信 |
|---|---|---|
| 利用者/アカウントデータ | 顧客環境 | 通常なし |
| ワークフロー | 顧客環境 | 通常なし |
| エージェント設定 | 顧客環境 | 通常なし |
| 業務データ | 顧客環境 | ワークフローによる |
| 運用ログ | 顧客環境 | 通常なし |
| 監査ログ | 顧客環境 | 通常なし |
| AIプロンプト | 顧客環境 / AIプロバイダー | 外部AI使用時はあり |
| AIの応答 | AIプロバイダー → 顧客環境 | あり |
| AIに送信された文書 | 顧客環境 / AIプロバイダー | あり |
| API認証情報 | 顧客環境 | 外部リクエストの認証に使用 |
| サポートファイル | 顧客が明示的に提供した場合にAkabotへ送信 | サポートのために提供された場合のみ |

「通常なし」は、データが環境外に出ることが一切ないことを意味するものではない。顧客が設定したワークフローにより、データが外部システムへ送信される場合がある。

## 5. ネットワーク接続

設定に応じて、次の接続が含まれることがある。

### 内部接続

- Studio → Center;
- Agent → Center;
- Center → データベース;
- AI Hub → 内部サービス;
- アプリケーション → Data Service。

### 外部接続

- AI Hub → AIプロバイダー;
- ライセンス供与サービス;
- 更新/パッケージリポジトリ;
- ワークフローが使用する外部API;および
- 顧客が設定するメール、ウェブまたはアプリケーションサービス。

## 6. 通信時の暗号化

機微なデータを伝送するHTTP接続には、HTTPS/TLSを使用するべきである。

顧客は、自らのインフラストラクチャにあるエンドポイントについて、証明書およびTLSを設定する責任を負う。

外部プロバイダーへの接続には、当該プロバイダーがサポートするセキュリティ機構が使用される。

## 7. 保存時の暗号化

保存時の暗号化は、次の要素に依存する:

- データベースの設定;
- オペレーティングシステム;
- ディスク/ストレージの設定;
- Kubernetes/ストレージプラットフォーム;
- クラウド/プライベートクラウドの設定。

必要な場合、顧客はインフラストラクチャ層における保存時の暗号化の有効化および管理について責任を負う。

## 8. 認証

バージョンおよび設定に応じて、製品はエンタープライズ環境に適した認証方式をサポートすることがある。

顧客は、次の事項について責任を負う:

- 利用者のライフサイクル管理;
- パスワードポリシー;
- IDプロバイダー;
- 設定されている場合の多要素認証(MFA);
- 管理者アカウント;および
- サービスアカウント。

## 9. 認可

製品は、サポートされる機能について、ロールベースアクセス制御またはこれに相当する仕組みを適用する。

顧客は、最小権限の原則を適用しなければならない。

管理者権限は、その必要のある担当者にのみ付与されるべきである。

## 10. シークレット管理

次の情報はシークレットとして取り扱われなければならない:

- パスワード;
- データベースの認証情報;
- APIキー;
- AIプロバイダーのキー;
- アクセストークン;
- 秘密鍵;
- クライアントシークレット。

シークレットへのアクセスは制限されなければならない。適切な保護機構が利用可能な場合、平文で保存してはならない。

## 11. ログ記録

システムは次を生成することがある:

- アプリケーションログ;
- エラーログ;
- 監査ログ;
- エージェントログ;
- ワークフローログ;
- AIリクエストのメタデータ。

顧客は、次の事項を定める責任を負う:

- ログの保持期間;
- ログへのアクセス;
- バックアップ;
- SIEM(セキュリティ情報イベント管理)との連携;および
- 監視。

認証情報または不要な機微データをログに記録してはならない。

## 12. AIデータフロー

### 12.1 リクエスト

利用者/ワークフロー  
→ AI対応機能  
→ AI Hub  
→ AIプロバイダーAPI。

### 12.2 処理

AIプロバイダーは必要な入力を受け取り、選択されたサービスに従って推論を実行する。

### 12.3 応答

AIプロバイダー  
→ AI Hub  
→ 呼び出し元アプリケーション/ワークフロー  
→ 顧客環境。

## 13. AIデータ管理

顧客は、次の事項を評価するべきである:

- プロバイダー;
- APIエンドポイント;
- モデル;
- 地域;
- 保持ポリシー;
- トレーニングポリシー;
- ゼロデータ保持(Zero Data Retention)の利用可否;
- ログ設定;および
- アカウントの種類。

同一プロバイダーの異なるモデルまたはAPIエンドポイントであっても、保持ポリシーが同一であるとは限らないため、その前提で判断するべきではない。

## 14. 外部AIプロバイダーマトリクス

| プロバイダー | 送信データ | 目的 | プロバイダー側で管理される保持期間 |
|---|---|---|---|
| OpenAI | 設定に応じたプロンプト/コンテキスト/ファイル | AI推論 | 該当するOpenAIのAPIポリシーおよび設定による |
| Google Gemini | 設定に応じたプロンプト/コンテキスト/ファイル | AI推論 | 該当するGeminiのAPIポリシーおよび設定による |
| その他のプロバイダー | 設定による | AI推論 | 当該プロバイダーのポリシーによる |

本マトリクスは、Akabotがプロバイダーを追加した場合に更新されるものとする。

## 15. ネットワークセキュリティ

顧客は、次の事項を実施するべきである:

- ファイアウォール;
- ネットワークセグメンテーション;
- 許可リスト;
- アウトバウンド接続の制限;
- 該当する場合の侵入検知/防御システム(IDS/IPS);
- TLS;
- セキュアDNS;および
- 管理アクセスの統制。

高いセキュリティ要件を有する環境については、AIプロバイダーへのアウトバウンドトラフィックを、承認されたドメインまたはエンドポイントに制限することができる。

## 16. 脆弱性管理

Akabotは、製品開発プロセスに適したセキュリティテストおよび脆弱性管理の活動を実施する。

顧客は、次の事項の脆弱性管理について責任を負う:

- オペレーティングシステム;
- データベース;
- ネットワーク機器;
- ハイパーバイザー;
- Kubernetesインフラストラクチャ;および
- 顧客が管理する第三者ソフトウェア。

## 17. バックアップおよび災害復旧

オンプレミス導入については、顧客が次の事項について第一次的責任を負う:

- バックアップスケジュール;
- バックアップの保持期間;
- リストアテスト;
- 災害復旧;
- 目標復旧時点(RPO);および
- 目標復旧時間(RTO)。

高可用性(HA)/データセンター間の災害復旧(DC-DR)に関する具体的な要件は、ソリューションアーキテクチャまたは契約において定めるものとする。

## 18. サポートアクセス

Akabotは、デフォルトでは顧客の環境に対する常時の管理者アクセス権を有しない。

リモートサポートが要求される場合:

1. 顧客がアクセスを承認する;
2. アクセスは必要な範囲に限定される;
3. アクセスに関する活動は顧客の手続きに従う;および
4. サポート完了後、アクセス権は失効されるべきである。

## 20. セキュリティインシデントに関する責任

Akabot製品に関するインシデントは、Akabotのインシデント対応プロセスに従って対応される。

顧客のインフラストラクチャに関するインシデントは、顧客が対応する。

AIプロバイダーまたは外部サービスに関するインシデントは、該当するプロバイダーのポリシーに従って対応される。

インシデントが複数の責任範囲に影響を及ぼす場合、両当事者は協力するものとする。

## 21. アーキテクチャの変更

本書は、次の場合に更新されることがある:

- 製品が追加または廃止された場合;
- AIプロバイダーが追加された場合;
- データフローが変更された場合;
- 導入アーキテクチャが変更された場合;
- クラウドサービスが追加された場合;または
- セキュリティ管理策が変更された場合。

本技術文書の更新自体は、顧客データの所有権、または契約に定める法的義務を変更するものではない。
