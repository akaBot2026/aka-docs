# ST-ANA-003 - プロジェクト ワークフロー数

**ルール ID：** ST-ANA-003

**スコープ：** プロジェクト

## 説明

このルールは、プロジェクト フォルダー内のワークフロー（`.xaml`）ファイルの総数をカウントしてリスト表示します。

エラーや警告をスローする他のルールとは異なり、このルールは主に**情報的なメトリクス**として機能します。プロジェクトのサイズと複雑さのクイック スナップショットを提供します。

![st-ana-003](/static/img/st-ana-003.png)

## 推奨事項 & ベスト プラクティス

ワークフロー数に厳格な「最大」制限はありませんが、このカウントを追跡することで RPA 開発者がコード品質とスケーラビリティを維持するのに役立ちます：

- **ワークフローが少なすぎる（例：1 つまたは 2 つ）：** 複雑なビジネス プロセスが単一の `Main.xaml` ファイルに完全に詰め込まれている場合、「モノリシック」ボット（スパゲッティ コード）になります。これにより、デバッグ、テスト、チームでの共同作業が非常に困難になります。**推奨：** ロジックを小さく再利用可能なワークフロー ファイルに分割してください。
- **ワークフローが多すぎる：** 逆に、比較的シンプルなプロセスに数十もの小さなワークフロー ファイルがある場合は、過剰な設計になっている可能性があり、実行パスを追跡することが困難になります。

コード レビュー中にこのメトリクスを使用して、プロジェクトが適切にモジュール化されていることを確認してください。理想的には REFramework などの標準的なアーキテクチャ パターンに従ってください。
