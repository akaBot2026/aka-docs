# AkaXtract が文書を「学習」する仕組み

AkaXtract は、お客様の文書でモデルの学習（トレーニング）やファインチューニングを**行いません**。学習用のデータセットを準備する必要はなく、学習の完了を待つ必要もありません。[Pipeline](./create-a-pipeline.md) で抽出する内容を記述し、新しいバージョンを公開した時点で変更が反映されます。

## 設定する項目

| 設定 | 制御する内容 |
| --- | --- |
| AI モデル | 文書を処理するモデルです。精度、対応言語、ページ数の上限は、モデルによって異なる場合があります |
| Classification のプロンプトとスキーマ | 各ページをどの文書タイプに割り当てるか、またページをどのように文書としてまとめるか |
| Extraction のプロンプト（文書タイプごと） | どのフィールドを探すか、値が欠けている場合の扱い、表の読み取り方 |
| Extraction JSON スキーマ（文書タイプごと） | フィールド名、データ型、結果の構造（ヘッダー フィールドと明細行など） |
| 後処理スクリプト（任意） | 抽出後の値の補正 |
| 承認ルール | どの結果を自動で完了し、どの結果をレビュー担当者に回すか |

## 精度を高める

1. 実際の文書を代表するサンプルから Pipeline を作成します。
2. 生成されたフィールド、名前、データ型が、受け取り側のシステムの要件に合っているか確認します。
3. サンプル文書で[テスト](./test-and-publish.md)し、データを元の文書と照合します。
4. フィールドが間違っている、または欠けている場合は、その文書タイプの抽出プロンプトまたはスキーマを変更します。必要なフィールド、欠損値の扱い、表データについて、より正確に記述してください。単純な補正には後処理スクリプトを使用します。それでも結果が十分でない場合は、別の AI モデルを選択して再度テストします。
5. もう一度テストしてから、公開します。
6. 検証している間は、`Auto-Approve Results` をオフにしておきます。結果を信頼できるようになったら、しきい値を設定してオンにします。[承認ルール](./create-a-pipeline.md#approval-rules)を参照してください。

## レビューでの修正の効果

[Review](../documents/review-and-export.md) での修正は、その 1 件の文書の結果だけを修正します。モデルは学習せず、Pipeline も変更されません。修正を今後の文書にも反映するには、新しい Draft でプロンプトまたはスキーマを変更し、テストして公開してください。
